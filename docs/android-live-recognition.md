# 安卓实时本地识别

2026-10-13：实现规划中的①实时本地识别；随后接入⑦的[基础试验规则](scope-basic-v1.md)。

## 使用

进入「识别 → 本地识别」，等待模型和相机就绪，开启「实时观察」。对准一个主要物品并稍停片刻，预览底部显示当前候选、置信度和确认进度。连续三帧类别一致，且每帧通过基础确认规则时，显示稳定类别；未通过时提示暂不确定。

开关默认关闭，仅保留当前识别页面会话中的选择；重新启动应用后关闭。切页、后台、选择图片、拍照、纠错弹层及切换云端会暂停分析并清空预览结果。回到本地取景页面后可继续。

实时画面不保存照片、不增加历史记录、不上传图片或识别结果。按「拍照识别」后，对保存照片重新推理，再走已有记录及同步流程；不会把上一帧预览预测写成照片结果。云端识别仍使用主动拍照或选择的图片。

## 处理与资源

- 复用唯一的本地 `campus-evolve-v2`、标签和 `rgb-letterbox-v1` 预处理；不增加模型文件或改变模型哈希。
- CameraX 使用低分辨率分析帧及 `STRATEGY_KEEP_ONLY_LATEST`；一个后台执行器串行分析，约每秒最多两次。慢设备按实测处理时间降低频率，不累计等待帧。[CameraX 官方说明](https://developer.android.com/media/camera/camerax/analyze)
- 预览、拍照和分析共享取景裁剪区域；分析帧先按 CameraX 裁剪、纠正旋转，再进入原有 RGB/灰色补边流程。
- 模型维护、重载或其他推理持锁时，预览尝试立即跳过，不排队争抢解释器。已开始的一次推理允许正常完成并释放资源，暂停后其结果不得回填。
- 每帧释放 `ImageProxy` 和临时 Bitmap，移除页面时解绑本页面用例并关闭执行器。设备不支持同时绑定分析用例时，回退预览和拍照，并提示实时功能不可用。
- 改变类别、低置信结果、过期结果及暂停均重置稳定计数。超过 2.5 秒没有新结果会清空旧提示。保留上一版真机取景区比例，短屏仍可滚动；模拟器像素分辨率相同但密度不同，页面缩放也会不同。

三帧确认通常额外等待约 1–2 秒，不等于单次推理耗时。连续一致不能证明分类正确；现有十类模型仍可能把范围外物品认成已知类别。本功能不提供目标检测、多主体识别或范围外拒绝。

## 验证记录

构建入口使用 `android/README.md` 中的 Windows 英文盘符方式。新增检查包括：串行限频、暂停后旧结果丢弃、慢帧过期、类别变化及低置信重置；设备检查使用真实 v2 样例、裁剪旋转像素检查和真实 CameraX 预览。

当前验证结果与安装包哈希登记在 `experiments/reports/deployment/campus-evolve-v2/android-live-recognition.json`。MuMu 为 1220×2656、280 dpi、Android 12L/API 32；标准长屏设备作为另一项布局与兼容性检查。模拟器不替代正式手机的识别准确率、耗电及性能验收。

真机建议连续运行 5–10 分钟，检查发热、相机稳定性和前后台恢复；按原验收规则另测预热 20 次、至少 100 次预处理与推理的 P50/P95。画面到三帧稳定提示的延迟需要单独计量。
