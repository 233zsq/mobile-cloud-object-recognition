# 模型交接约定

由模型训练负责人提供，Android开发负责人接入手机，数据与云端负责人部署云端CPU推理，组长验证。当前只有约定与模板，没有正式模型。

## 类别与输出

类别 ID 暂定 0 至 9，正式映射由 `shared/categories.json` 冻结后生成。`shared/categories.example.json` 是草案，不能直接用于正式标注。

`labels.txt` 每行是一个 `label_key`，第 0 行对应输出索引 0；数据库类别 ID、Android 预测映射与模型输出索引一致，中文显示名称来自相同版本的类别清单。模型包保存类别版本与标签文件 SHA-256。

## 输入与预处理

计划基线为 RGB、224×224×3，正式形状与类型以导出模型实际张量为准。交接时明确图片方向处理、裁剪规则、缩放方法、颜色通道顺序、归一化公式及处理是在模型内还是模型外，避免重复归一化。

首版计划使用浮点模型；如果输出量化模型，另行记录输入输出的 scale 和 zero point，按实际张量规格编码、解码。不能将浮点输入规则直接用于量化模型。

## 发布包

- `model.tflite`、`labels.txt`、`metadata.json` 和评估结果。
- 模型版本、SHA-256、类别版本、数据版本、实验 ID 与代码提交。
- 实际输入输出形状、数据类型、输出解释、完整预处理与量化参数。
- 验证集确定的低置信阈值、导出环境版本、PC/Android/云端同图对照结果及不一致记录。

元数据模板见`models/metadata.template.json`，所有空值由实际导出和验证后填写。手机与云端使用同一份FP32 tflite、labels.txt和预处理说明；接收方校验哈希、标签数与输出维度，再用同批图片核对PC、手机和云端结果。量化版本另行标记，不能混入部署位置的基线比较。

最终测试集只用于冻结后的评估；量化校准使用训练样本。首版模型随 APK 打包，正式模型文件通过组内共享存储领取并复制到 `android/app/src/main/assets/models/`。

云端领取相同发布包，模型路径由配置提供，启动时校验并加载。计时先预热20次，再测至少100次；记录设备、运行时、线程、纯推理、预处理加推理及手机端网络总等待时间。记录云端CPU、内存和失败率，不能预设云端更快或更准确。
