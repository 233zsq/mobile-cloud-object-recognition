# v3 范围判断与双模型交接

`campus-evolve-v3` 保留 v2 的 MobileNetV2 和原10类分类权重，增加一个独立的范围判断输出。它解决的是类别外图片被高置信度硬分到10类的问题，不提高原分类器的已知类准确率。用户于2026年10月13日批准发布，要求安卓本地及云端均可选择 v2/v3，默认 v3；v2 保留原始模型字节及基础规则。

## 已测结果

| 指标 | v2 基础规则 | v3 范围判断 |
| --- | ---: | ---: |
| 相同609张已知验证图原始准确率 | 91.46% | 91.46% |
| 原始宏平均 F1 | 0.9126 | 0.9126 |
| 已知图自动通过 | 584/609 | 556/609 |
| 已知图需确认 | 25/609 | 53/609 |
| 相同400张公开类别外保留图被拦截 | 130/400（32.5%） | 391/400（97.75%） |
| 壁虎开发样例 | 钥匙，99.9914%，自动通过 | 保留同一原始候选，范围分数0.4291，需确认 |

已知验证图参与了阈值选择，以上不是独立实拍验收。公开类别外保留图来自一个数据源，仍有9张误通过；不能据此保证任意类别外照片都能被拦住。范围分数也不是经过真实场景校准的概率。笔袋/钥匙等各类覆盖率及所有10类指标、混淆矩阵见 `experiments/reports/open-set-v3/independent-runtime.json`。

模型9,531,856字节。独立 Windows LiteRT 2.2.0 复核全部609+400张，分类分数与 v2 完全一致。20张交接样例的模拟器参考张量及完整图片链路最大分数差均小于0.001；模拟器预热20次、测量100次，含解码/预处理/推理 P95 为25.81ms。它不是物理手机性能验收。

## 训练与隔离

采用冻结骨干的最终池化特征及 `block_15_expand_relu` 池化特征，拼成2240维，接标准化、64维 ReLU、Dropout 0.2 和二分类 Sigmoid。仅训练范围判断头；原模型及 BN 全部冻结。Adam 0.0003、batch32、最多20轮、验证损失连续3轮不改善早停。种子42比较线性/MLP候选，按开发校准集选择；种子43复核胜出 MLP，已知自动通过率相差2.13个百分点，类别外校准集拒绝率均为99.5%。种子43阈值为其独立校准结果，不替换发布种子42的规则。

辅助数据来自 [Caltech101 官方记录](https://data.caltech.edu/records/mzrjq-6wc02)，下载使用 [fastai 官方列出的镜像](https://github.com/fastai/fastai/blob/master/fastai/data/external.py)。来源没有明确许可声明，原始照片及归档保留本地，不进入 Git 或公开发布包。辅助 v2 划分：1200张训练、200张校准、400张保留评估；三部分按来源语义类别隔离，SHA及感知哈希去重，但不能证明实物身份隔离。项目正式 COCO/实拍测试图片未读取、未调参。

首次只用深层特征的候选仍会接受壁虎，已保留失败报告。第二轮将首轮开发保留类别明确降为训练数据，并使用新的20个来源类别作为400张保留评估；不能将两轮不同保留集的结果直接作提升比较。`data/ood/` 保存两版清单、源归档哈希及限制。

先用已知验证集及200张未知校准图选阈值，再冻结 `selection.json`，随后打开400张保留评估图。壁虎只在选择完成后诊断，没有参与训练或阈值选择。发布规则固定分类最高分≥0.55、前两名差≥0.20、范围分数≥0.8500000238418579。

## 输出与确认

输入仍为 float32 `[1,224,224,3]` RGB 0–255，沿用 `rgb-letterbox-v1`，归一化在模型内部。输出位置以 TFLite 输出列表的**序号**为准：v3 `score_output_index=1` 为 `[1,10]`；`scope_output.index=0` 为 `[1,1]`，不能把它们当张量内部ID。v2仍为单输出。

类别及索引完全不变。“不确定”是决策状态，不是第11类。API 返回 `recognition_status` 及 `scope_decision`，保留原 Top-1、完整分数、模型身份和范围分数。客户端核对模型及规则身份并重新计算判断；规则缺失时需人工确认。未确认结果只留在当前会话，不建立记录或上传，用户可以确认候选、改选真实类别或丢弃。

确认后的上传可附 `scope_decision`，保存初始状态、规则版本/哈希、范围分数及人工确认标志。原8个记录字段不变。旧记录标为 `unreported`，不按置信度推测其历史判断。安卓 Room 2→3 及 MySQL `002_inference_decision.sql` 均为增加字段/表。数据库迁移先于新后端；旧客户端重传不能抹掉已保存的判断信息。

## 复现与发布

1. 用 `scripts/prepare-open-set-data.py --help` 生成辅助 v2 数据，核对冻结清单哈希；保持已知 `campus-evolve-data-v2` 不变。
2. 在既有 GPU 环境运行 `scripts/train-open-set.py`，指定原 v2 Keras 检查点、辅助数据及 `--early-layer block_15_expand_relu`。路径和原图留在本地。
3. 用独立 CPU 环境运行 `scripts/verify-open-set.py`，对相同已知验证/未知保留数据比较 v2/v3；脚本只评估，不重新选择阈值。
4. `scripts/recheck-open-set-seed.py` 复用冻结特征进行种子43复核，不打开保留或正式测试图。
5. `scripts/package-open-set.py` 与 `scripts/prepare-open-set-handover.py` 先生成试验包和20张参考样例。人工批准后，批准记录绑定模型、规则及比较报告哈希。部署校验拒绝未批准试验包。
6. 安卓内置两个包，加载一个活动解释器；切换等当前推理结束后替换模型与规则，选择保存在本机。未确认照片及识别中禁止切换。记录以实际预测使用的版本为准。
